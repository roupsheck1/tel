## ۱. خلاصه اجرا

سامانه ماژولار دریافت محتوای اینستاگرام و تحویل در تلگرام، طبق سند «دستورات ۲» آماده شد. در این نسخه نسبت به وضعیت قبلی، **حلقه کامل پرداخت دستی بسته شد** (بخش ۱۳ سند: گام‌های ۸ تا ۱۱) و منوی پنل به ۱۲ بخش سند (۱۶.۲) رسید.

- **معماری:** Python + aiogram 3 + SQLite (مهاجرت نسخه‌بندی‌شده) + صف پایدار در پایگاه داده + workerهای async + instagrapi (روش اصلی، API خام) + yt-dlp (پشتیبان، با کوکی نشست) + Docker/Podman.
- **اصول غیرقابل‌مذاکره (بخش ۱):** بدون تحویل متقاطع فایل (اتصال یک‌به‌یک IG↔TG با کد یک‌بارمصرف)، مجوز سمت سرور برای هر عملیات پنل، اسرار فقط در متغیرهای محیطی، عملیات مالی اتمیک/ایدمپوتنت، بازیابی صف پس از restart.

## ۴. قابلیت‌های آزمون‌نشده (صادقانه — بخش ۲۱.۳ سند)

1. **دریافت دایرکت واقعی و دانلود با نشست واقعی:** منطق کامل آزمون‌شده، اما نشست اکانت `momplyf_43` فقط در محیط استقرار (متغیرهای محیطی Lucity) وجود دارد؛ از این محیط قابل آزمون نبود. **الزام عملیاتی: پس از استقرار، یک پست عکس و یک ریلز واقعی بفرستید.**
2. **تعامل واقعی UI پنل در تلگرام:** منطق مجوز و کارت سفارش آزمون‌شده؛ کلیک واقعی دکمه‌ها نیازمند توکن واقعی است.
3. **ارسال فایل نزدیک ۲ گیگابایت:** مسیر آماده (Local Bot API در compose)؛ آزمون واقعی نشده.

## ۵. محدودیت‌های خارجی (بخش ۲۱.۴)

- **yt-dlp فقط ویدیو:** عکس‌ها فقط از مسیر instagrapi (نیازمند نشست سالم). اگر نشست منقضی شود، عکس‌ها خطای واضح می‌دهند (نه سکوت).
- **اینستاگرام درخواست بی‌نشست را مسدود می‌کند** («empty media response») — کوکی نشست الزامی است.
- **Bot API رسمی تلگرام سقف آپلود ۵۰MB** دارد؛ فایل بزرگ‌تر خودکار فشرده می‌شود (ffmpeg 720p) یا Local Bot API لازم است.
- کتابخانه instagrapi غیررسمی است؛ ریسک تغییر API پلتفرم همیشه هست (خطاها طبقه‌بندی و گزارش می‌شوند).

## به‌روزرسانی پرده سوم — رفع باگ UI و بازآرایی متن‌ها (۲۰۲۶-۱۰-۲۹)

### رفع باگ‌های دکمه (سمت تلگرام واقعی)
- **«🏠 منوی اصلی» و «❌ انصراف» بی‌پاسخ بودند:** کیبورد `a:home:` / `a:cancel:` می‌فرستاد ولی هندلر فقط `a:home` / `a:cancel` را می‌پذیرفت (عدم تطابق دونقطه پایانی). هندلرها به پذیرش هر دو شکل اصلاح شدند؛ آزمون رگرسیون `tests/test_ui_wiring.py` همه ۹۷ دکمه استخراج‌شده از سورس را با دیسپچر واقعی تطبیق می‌دهد.
- **پاک‌سازی FSM:** بازگشت به منوی اصلی حالت ورودی نیمه‌کاره (AdminInput) را هم پاک می‌کند تا ورودی بعدی به جریان قدیمی نرود.
- **توقف انیمیشن انتظار:** `edit_or_answer` ابتدا callback را answer می‌کند تا روی دکمه‌ها ساعت شمار بی‌پایان نماند.

### بازآرایی متن‌های ربات (سبک یکسان: عنوان + فیلدهای شماره‌دار 1️⃣…7️⃣ + «📌 نمونه»)
- ساخت پلن جدید (فقط ۷ فیلد به شکل `name: gold` چندخطی؛ شکل قدیمی `|` هم پذیرفته می‌شود)، ساخت کد اشتراک، استثنای فردی، ظرفیت سرور، گروه دستی، افزودن مدیر، حالت رایگان، تمدید، تغییر قیمت، زمان‌بندی فروش، پیگیری درخواست، رد سفارش، پیام همگانی.
- پیام‌های پیش‌فرض کاربر: خوشامد (۳ مرحله اتصال)، راهنما، قالب پرداخت (۲ مرحله پس از پرداخت)، متن اتصال (`/connect`).
- ورودی‌ها: ارقام فارسی پذیرفته می‌شود؛ جداکننده «:» علاوه بر «=» در همه فرم‌های کلید-مقدار.
- یوزرنیم واقعی پیج اینستاگرام در متن خوشامد جایگزین عبارت عمومی شد (`bot.ig_username`).

### آزمون‌های جدید (۱۶)
`tests/test_ui_wiring.py`: مسیریابی `a:home:`/`a:cancel:` (هر دو شکل)، تطبیق همه دکمه‌های ثابت پنل و دکمه‌های کاربر با هندلرها، پارسر پلن جدید (کلید:مقدار فارسی/انگلیسی، ارقام فارسی، شکل قدیمی، ورودی ناقص)، parse_kv با «:» و ارقام فارسی.
