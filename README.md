# ربات دریافت محتوای اینستاگرام و ارسال به تلگرام

سامانه جامع دریافت پست و ریلز اینستاگرام از طریق **دایرکت اینستاگرام** و تحویل فایل در **چت خصوصی تلگرام**، همراه با سیستم اشتراک، فروش دستی، موتور مدیریت دانلود با صف پایدار و پنل مدیریت کامل داخل تلگرام.

- زبان رابط کاربری: فارسی (راست‌چین)
- نسخه: 1.0.0
- پشته فناوری: Python 3.12، aiogram v3، instagrapi، yt-dlp، SQLite، Docker

---

## ۱. معرفی پروژه

کاربر پست یا ریلز موردنظر را در دایرکت اینستاگرام برای پیج ربات می‌فرستد و سامانه پس از بررسی اشتراک و محدودیت‌ها، فایل را در چت خصوصی ربات تلگرام تحویل می‌دهد. مدیریت کامل سامانه (کاربران، پلن‌ها، قیمت‌ها، سفارش‌ها، کدها، گروه‌ها، پیام همگانی، سلامت سامانه) از داخل تلگرام و با Inline Keyboard انجام می‌شود.

**نکته معماری مهم:** طبق طراحی، منبع اصلی دریافت محتوا فقط دایرکت اینستاگرام است؛ ارسال لینک در تلگرام جزو جریان اصلی این نسخه نیست و در صورت ارسال لینک، کاربر راهنمایی می‌شود.

## ۲. قابلیت‌ها

| حوزه | قابلیت |
|------|---------|
| کاربران | ثبت‌نام خودکار با /start، حفظ تاریخ ثبت‌نام، مسدودسازی، اتصال یک‌به‌یک اینستاگرام با کد ۶ رقمی |
| اشتراک | پلن‌های نسخه‌دار، تمدید انباشتی، هدیه، کد اشتراک، دوره آزمایشی با کنترل سوءاستفاده |
| فروش | سه حالت رایگان/زمان‌بندی‌شده/فوری، سفارش با اسنپ‌شات روش پرداخت، رسید، تأیید/رد اتمیک مدیر |
| دانلود | صف پایدار در DB، سه محدودیت مستقل (هم‌زمانی/انتظار/سهمیه)، ظرفیت کلی سرور، اولویت منصفانه، تلاش مجدد، بازیابی پس از ری‌استارت |
| پنل | ۱۰ بخش کامل با کنترل مجوز سمت سرور، ۵ نقش سیستمی + نقش سفارشی |
| عملیات | گزارش خطا، رویداد مدیریتی (audit)، مرکز سلامت، پیام همگانی با پیش‌نمایش و توقف |

## ۳. معماری

```
app/
├── main.py               # مونتاژ و راه‌اندازی
├── config.py             # تنظیمات محیطی (pydantic-settings)
├── logging_config.py     # لاگ با ماسک خودکار اطلاعات محرمانه
├── schedulers.py         # زمان‌بندها (فروش، انقضا، سیاست گروهی، یادآوری)
├── database/             # SQLite + مهاجرت نسخه‌بندی‌شده + repository ها
├── instagram/            # کلاینت instagrapi، پایش دایرکت، دانلودر چندروشی
├── telegram/             # هندلرهای کاربر، پنل ادمین، ارسال فایل، میدل‌ور
├── services/             # منطق دامنه (پلن، اشتراک، سفارش، گروه، موتور صف ...)
└── admin/                # نقش‌ها و مجوزها
tests/                    # ۶۱ آزمون واحد/یکپارچگی
```

تفکیک مسئولیت‌ها مطابق بخش ۴ سند مشخصات؛ همه فراخوانی‌های بیرونی (دانلود/ارسال) از طریق قرارداد (Protocol) تزریق می‌شوند و آزمون‌پذیرند.

## ۴. پیش‌نیازها

- Python 3.12+
- ffmpeg (برای فشرده‌سازی خودکار ویدیوهای بزرگ)
- یک توکن ربات از [@BotFather](https://t.me/BotFather)
- یک اکانت اینستاگرام **مخصوص ربات** (ایمیل و شماره جدا توصیه می‌شود)
- در صورت نیاز به پروکسی: یک پروکسی HTTP/SOCKS (مثل v2ray)

## ۵. نصب (اجرای محلی)

```bash
git clone <آدرس-مخزن> && cd tel
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"        # یا: pip install aiogram instagrapi yt-dlp pydantic-settings
```

## ۶. تنظیم متغیرهای محیطی

```bash
cp .env.example .env
```

سپس مقادیر واقعی را در `.env` قرار دهید:

| متغیر | توضیح |
|-------|-------|
| `TELEGRAM_BOT_TOKEN` | توکن ربات از BotFather |
| `TELEGRAM_BOT_USERNAME` | یوزرنیم ربات بدون @ (نمایشی) |
| `INSTAGRAM_USERNAME` / `INSTAGRAM_PASSWORD` | اکانت اینستاگرام ربات |
| `INSTAGRAM_2FA_CODE` | اختیاری؛ اگر دومرحله‌ای فعال است |
| `ADMIN_IDS` | شناسه عددی مدیران اولیه با کاما |
| `PROXY` | اختیاری؛ مثل `http://127.0.0.1:3062` |
| `TELEGRAM_BASE_URL` | اختیاری؛ برای Local Bot API و فایل تا ۲ گیگ |

فایل `.env` هرگز نباید در Git قرار گیرد (در `.gitignore` مسدود است).

## ۷. راه‌اندازی محلی

```bash
python -m app.main
```

اولین اجرا: پایگاه داده ساخته، نقش‌ها و مدیران seed و سه پلن نمونه (آزمایشی/پایه/حرفه‌ای) ایجاد می‌شود.

## ۸. استقرار با Docker

```bash
cp .env.example .env   # تکمیل مقادیر
docker compose up -d --build
docker compose logs -f bot
```

داده‌های پایدار (پایگاه داده، سشن اینستاگرام، فایل‌های موقت) در volume به نام `bot-storage` نگه داشته می‌شوند و بازسازی کانتینر آن‌ها را از بین نمی‌برد.

## ۹. راه‌اندازی سرویس اینستاگرام

1. اکانت مخصوص ربات بسازید و حداقل یک‌بار وارد شوید.
2. اطلاعات آن را در `.env` قرار دهید.
3. ربات را اجرا کنید؛ در اولین ورود، نشست در `storage/ig_session.json` ذخیره می‌شود و اجراهای بعدی بدون ورود مجدد انجام می‌شود.
4. اگر دومرحله‌ای دارید، کد را در `INSTAGRAM_2FA_CODE` بگذارید.

**محدودیت شناخته‌شده:** instagrapi یک کتابخانه غیررسمی است؛ دریافت دایرکت آن سرویس رسمی تضمین‌شده نیست و ممکن است با تغییرات اینستاگرام دچار اختلال شود. این ریسک در بخش ۲۰ مرکز سلامت قابل پایش است (آخرین اسکن/خطا).

## ۱۰. راه‌اندازی سرویس تلگرام

1. از [@BotFather](https://t.me/BotFather) ربات بسازید و توکن را در `.env` بگذارید.
2. `/setprivacy` را روی **Disable** بگذارید تا ربات پیام‌های متنی را ببیند.
3. اجرا → پیام `/start` → ثبت‌نام خودکار.

## ۱۱. پیکربندی دریافت دایرکت

- فاصله پایش: `IG_POLL_MIN` / `IG_POLL_MAX` (پیش‌فرض ۳۰ تا ۶۰ ثانیه تصادفی).
- پیام‌های دیده‌شده در جدول `ig_seen` ردیابی می‌شوند (بدون پردازش تکراری).
- درخواست‌های pending دایرکت خودکار تأیید و پردازش می‌شوند.
- کاربر وصل‌نشده فقط کد اتصال می‌گیرد؛ کاربر وصل‌شده، پست/ریلز او به صف می‌رود.

## ۱۲. تنظیم پنل مدیران

- شناسه عددی مدیران در `ADMIN_IDS` → نقش «مدیر اصلی».
- ورود به پنل: دستور `/panel`
- افزودن مدیر بعدی: پنل → 🔐 مدیریت مدیران → ➕ (شکل: `شناسه نقش` مثل `123456 sales`)
- نقش‌های آماده: `owner`، `tech`، `support`، `subs_manager`، `sales`

## ۱۳. ایجاد پلن

پنل → 💎 اشتراک‌ها → ➕ پلن جدید → یک خط:

```
gold | طلایی | 299000 | 30 | 2 | 10 | 15
```

ترتیب فیلدها: نام داخلی | عنوان | قیمت تومان | مدت روز | دانلود هم‌زمان | انتظار ثانیه | ظرفیت صف

## ۱۴. مدیریت نسخه پلن

- تغییر قیمت → ساخت نسخه جدید **پیش‌نویس** (سفارش‌های قبلی با قیمت لحظه خرید می‌مانند).
- انتشار پیش‌نویس با انتخاب دامنه: فقط خریداران آینده / فقط مشترکان فعلی / هر دو.
- تاریخچه نسخه‌ها در کارت پلن قابل بازبینی است.

## ۱۵. ساخت اشتراک آزمایشی

- پلنی با تنظیم `is_trial` (مثل پلن seed «آزمایشی ۱ روزه») بسازید.
- دریافت آزمایش برای هر کاربر فقط یک‌بار ثبت می‌شود (جدول `trial_grants`).
- دکمه دریافت آزمایش در فهرست پلن‌ها به کاربر نمایش داده می‌شود.

## ۱۶. مدیریت گروه‌های کاربری

گروه‌ها سه نوع‌اند: بازه زمانی ثبت‌نام (نسل‌ها)، فیلتر وضعیت (مشترک فعال/بدون اشتراک/...) و دستی. برای هر گروه می‌توان سیاست (هدیه اشتراک/تمدید) با **پیش‌نمایش تعداد مشمول** و اجرای فوری یا زمان‌بندی‌شده تعریف کرد؛ اجرا در `group_policies` تاریخچه دارد.

> ساخت گروه‌ها از طریق سرویس `GroupService` و API برنامه‌نویسی انجام می‌شود؛ خلاصه وضعیت گروه‌ها در پنل → 📊 آمار → 👥 قابل مشاهده است.

## ۱۷. ثبت سفارش (جریان کاربر)

1. کاربر: `/plans` → انتخاب پلن → ایجاد سفارش یکتا با اطلاعات کارت (اسنپ‌شات).
2. دکمه «پرداخت کردم» → وضعیت: پرداخت اعلام‌شده + اعلان خودکار به مدیران دارای مجوز تأیید.
3. ارسال عکس رسید → رسید به همان سفارش متصل می‌شود (بدون تأیید خودکار) + اعلان مجدد به مدیران با دکمه‌های سریع تأیید/رد.
4. مدیر از پنل (بخش ۱۹) تأیید یا رد می‌کند؛ نتیجه به کاربر اطلاع داده می‌شود (گام‌های ۸ تا ۱۱ بخش ۱۳ سند).
5. پس از ثبت درخواست دانلود، کاربر «شناسه پیگیری» (#عدد) می‌گیرد تا در پیگیری مشکلات به پشتیبانی بدهد (بخش ۵۶ سند ۲).

## ۱۸. بررسی پرداخت دستی (مدیر) — بخش ۴ پنل

پنل → 🧾 سفارش‌ها و پرداخت‌ها:

- 🔔 **در انتظار بررسی**: همه سفارش‌های دارای رسید/اعلام پرداخت، جدیدترین اول.
- 🧾 **کارت سفارش**: مشخصات کاربر، پلن، مبلغ، روش پرداخت، وضعیت و زمان‌ها — مدیر قبل از تأیید همه چیز را می‌بیند (۱۳.۷).
- 🖼 **مشاهده رسید**: عکس رسید فقط برای مدیران دارای مجوز ارسال می‌شود (۲۵.۶ سند ۲).
- ✅ **تأیید پرداخت**: با تأییدیه دومرحله‌ای؛ اشتراک فعال/تمدید و کاربر مطلع می‌شود؛ **تأیید چندباره فقط یک اشتراک می‌سازد** (گارد وضعیت + تراکنش اتمیک — آزمون‌شده).
- ❌ **رد سفارش**: با دلیل الزامی؛ دلیل برای کاربر ارسال می‌شود و در audit_log ثبت می‌گردد.
- 🔁 **علامت‌گذاری «نیازمند بررسی دستی»**: وضعیت مستقل برای موارد مبهم (۱۳.۶).
- 📊 **خلاصه وضعیت**: تعداد به تفکیک وضعیت + فروش تأییدشده + میانگین زمان بررسی + فروش به تفکیک پلن.

مجوزها (سمت سرور، بخش ۱۹.۴): مشاهده/رسید → `view_orders`، تأیید → `approve_payment`، رد → `reject_payment`.

## ۱۹. مدیریت صف

پنل → 📥 دانلودها: وضعیت لحظه‌ای صف/فعال/خطا، تلاش مجدد درخواست‌های ناموفق، تنظیم ظرفیت کلی سرور (دانلود فعال/ارسال فعال/سقف کل صف).

## ۲۰. محدودیت دانلود

هر پلن به‌صورت مستقل تنظیم می‌شود: دانلود هم‌زمان، زمان انتظار (صفر = بدون انتظار)، سقف صف، سهمیه ساعتی/روزانه/کل، حداکثر حجم فایل، اولویت. نقطه شروع زمان انتظار (شروع دانلود/پایان دانلود/پایان موفق ارسال) از پنل → 🛠 → ⏱ قابل تغییر است. استثنای فردی کاربر از پنل → 👥 → کارت کاربر → ⚡️.

## ۲۱. تنظیم ارسال فایل حجیم

- پیش‌فرض (Bot API رسمی): سقف آپلود بات **۵۰ مگابایت**؛ فایل بزرگ‌تر خودکار با ffmpeg تا 720p فشرده می‌شود و در صورت نشدن، خطای شفاف داده می‌شود.
- هدف ۲ گیگابایت: سرویس **Telegram Local Bot API Server** را در `compose.yaml` فعال کنید (نیازمند `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` معتبر از my.telegram.org) و `TELEGRAM_BASE_URL` را تنظیم کنید.
- وضعیت واقعی: مسیر ۲ گیگ فقط پس از راه‌اندازی Local Bot API و آزمون واقعی معتبر است.

## ۲۲. پشتیبان‌گیری

```bash
# داخل کانتینر یا روی سرور
sqlite3 storage/bot.db ".backup storage/backup_$(date +%F).db"
# یا با Docker:
docker compose exec bot python -c "from app.database import Database; Database('storage/bot.db').backup_to('storage/backup.db')"
```

زمان‌بندی پیشنهادی: cron روزانه + کپی به مقصد امن.

## ۲۳. بازیابی

```bash
cp storage/backup_YYYY-MM-DD.db storage/bot.db   # هنگام توقف ربات
docker compose restart bot
```

فایل‌های `ig_session.json` (نشست اینستاگرام) و `bot.db` با هم پشتیبان شوند.

## ۲۶. محدودیت‌های فنی شناخته‌شده

1. دریافت دایرکت مبتنی بر instagrapi (غیررسمی) است و تضمین پلتفرمی ندارد.
2. سقف آپلود بدون Local Bot API: ۵۰ مگابایت (فشرده‌سازی خودکار تا سقف).
3. پشتیبانی از استوری در این نسخه پیاده‌سازی نشده (پست/ریلز/آلبوم فعال است).
4. پرداخت خودکار در معماری پیش‌بینی شده اما پیاده‌سازی نشده (فروش دستی فعال است).
5. ارسال لینک از تلگرام جزو این نسخه نیست (طراحی، طبق بخش ۲.۱ سند).
6. تعداد هم‌زمان کل سرور برای SQLite باید کم (~ده‌ها عملیات هم‌زمان) بماند.
